# Reproducible release build (Linkwave website)

This repository is the **single versioned source** for the Linkwave website build. The
generator and its data modules live in `tools/`; all generated pages are committed so the
site is also directly deployable.

## Requirements

- Python 3.9+ (standard library only for the build; Pillow is only needed if a future owner
  refresh of photographs is performed, not for the normal build)
- Git with the repository history (the build extracts the frozen baseline commit)

Build-time configuration lives in `tools/build-config.json` (currently the exact CSP
`connect-src` origin for the FormSubmit delivery service). The wrapper passes it to the
generator, so a fresh clone reproduces the committed CSP byte-for-byte.
No file outside this repository is required. The approved optimized images already
committed under `images/linkwave/` are the versioned assets; the original owner-supplied
photographs are retained outside the repository for provenance only and are **not** needed
to rebuild the site.

## Build & verify (fresh clone)

```bash
git clone <this-repository> linkwave && cd linkwave
python tools/build_release.py --check --repeat
```

`--check` builds the site from the frozen baseline commit `da5ee8b` into a temporary
directory, validates the expected structure (19 EN pages, 18 AR pages, 51 generated text
files, 36 sitemap URLs, 6 Hero slides, 10 service rows) and compares every generated text
file with the committed working tree. `--repeat` builds twice and proves byte-identical
determinism.

Apply the build to the working tree (only when intentionally regenerating):

```bash
python tools/build_release.py --apply
```

Seal a manifest of the exact outputs:

```bash
python tools/build_release.py --manifest tools/build-manifest.json
```

## Why the baseline is used

The generator transforms the original pre-redesign pages (`da5ee8b`) into the current
site. It must not run in-place against already-generated pages. The wrapper handles the
baseline extraction with `git -c core.autocrlf=false archive`, so the extracted sources keep
LF line endings on every platform; this was required to reproduce the committed output
byte-for-byte on Windows.

## What is generated

- 18 English content pages + `404.html`; 18 Arabic pages under `ar/`
- `css/linkwave.css` (plus updated shared CSS), `js/content.js`, `js/linkwave.js`
- `sitemap.xml` (36 URLs), `robots.txt`, `site.webmanifest`, `THIRD-PARTY-NOTICES.txt`

Everything else (images, fonts, `.nojekyll`, `CNAME`) is versioned directly and is not
generated by the build.

## Verification (optional, development environment)

`tools/verify_release.cjs` runs the full Playwright regression suite against a local
preview of the working tree (`BASH`: `BASE_URL`, `SITE_ROOT`, `OUT_DIR`,
`PLAYWRIGHT_MODULE` environment variables; Playwright is a local dev-only dependency and is
not required to build or deploy the site).

## Security / provenance notes

- The build reads only repository files; it performs no network access and contains no
  credentials or secrets.
- Original owner-supplied photographs (`UPDATE/`) and the source hero photographs are not
  committed: they are not build inputs, they are large proprietary image sources, and the
  approved optimized derivatives are committed as the versioned website assets.
- `tools/build-manifest.json` records the baseline commit, tool hashes and expected output
  hashes/aggregate for the release candidate.
